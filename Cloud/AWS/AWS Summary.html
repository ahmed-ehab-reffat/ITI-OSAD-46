D. Traditional IT Infrastructure Concepts

How Websites Work:

Clients and Servers communicate over a network. Both Clients and Servers have IP addresses.

What is a server composed of?

  • Compute: CPU.
  • Memory: RAM.
  • Storage: Data.
  • Database: Store data in a structured way.
  • Network: Routers, switch, DNS server.

IT Terminology

  • Network: Cables, routers, and servers connected with each other.
  • Router: A networking device that forwards data packets between computer networks. They know where to send your packets on the internet.
  • Switch: Takes a packet and sends it to the correct server / client on your network.

Problems with traditional IT approach

  • Costs associated with: rent for the data center, power supply, cooling, maintenance.
  • Adding and replacing hardware takes time.
  • Scaling is limited.
  • Need to hire 24/7 team to monitor the infrastructure.
  • Difficulty dealing with disasters (earthquake, power shutdown, fire, etc.).

2. What is Cloud Computing?

A. Definition and Core Components

  • Cloud computing is the on-demand delivery of compute power, database storage, applications, and other IT resources.
  • It utilizes a cloud services platform with pay-as-you-go pricing.
  • Resources can be accessed instantly, provisioned exactly to the right type and size.
  • Amazon Web Services owns and maintains the network-connected hardware.

B. Deployment Models

  • Private Cloud:
    • Cloud services used by a single organization, not exposed to the public.
    • Provides complete control, security for sensitive applications, and meets specific business needs.
  • Public Cloud:
    • Cloud resources owned and operated by a third-party cloud service provider delivered over the Internet.
  • Hybrid Cloud:
    • Keep some servers on premises and extend some capabilities to the Cloud.
    • Offers control over sensitive assets in private infrastructure combined with flexibility and cost-effectiveness of the public cloud.
    • Often used during long cloud migrations, due to security requirements, compliance requirements, or IT strategy.

C. The Five Characteristics of Cloud Computing (Exam Focus)

  1. On-demand self service: Users provision resources without human interaction from the service provider.
  2. Broad network access: Resources are available over the network and accessible by diverse client platforms.
  3. Multi-tenancy and resource pooling: Multiple customers share the same physical infrastructure and applications with security and privacy.
  4. Rapid elasticity and scalability: Resources are automatically and quickly acquired and disposed of when needed; scales easily based on demand.
  5. Measured service: Usage is measured, ensuring users pay correctly for what they have used.

D. Six Advantages of Cloud Computing (Exam Focus)

  1. Trade capital expense (CAPEX) for operational expense (OPEX) (Pay On-Demand; don't own hardware).
  2. Benefit from massive economies of scale (prices reduced as AWS is more efficient due to large scale).
  3. Stop guessing capacity (scale based on actual measured usage).
  4. Increase speed and agility.
  5. Stop spending money running and maintaining data centers.
  6. Go global in minutes by leveraging the AWS global infrastructure.

E. Types of Cloud Computing (Service Models)

  1. Infrastructure as a Service (IaaS):
    • Provides building blocks for cloud IT (networking, computers, data storage space).
    • Highest level of flexibility; easy parallel with traditional on-premises IT.
    • Managed by you: Applications, Data, Runtime, Middleware, O/S.
    • Examples: Amazon EC2, GCP, Azure.
  2. Platform as a Service (PaaS):
    • Removes the need to manage the underlying infrastructure.
    • Focus on deployment and management of applications.
    • Managed by you: Applications, Data.
    • Examples: Elastic Beanstalk (on AWS), Heroku, Google App Engine (GCP).
  3. Software as a Service (SaaS):
    • Completed product run and managed by the service provider.
    • Managed by you: None.
    • Examples: Many AWS services (ex: Rekognition for Machine Learning), Google Apps (Gmail), Dropbox, Zoom.

3. AWS Global Infrastructure

A. Infrastructure Components

The global infrastructure consists of AWS Regions, AWS Availability Zones, AWS Data Centers, and AWS Edge Locations / Points of Presence.

B. AWS Regions

  • A Region is a cluster of data centers.
  • Names can be us-east-1, eu-west-3, etc..
  • Most AWS services are region-scoped.
  • How to choose a Region:
    • Compliance with data governance and legal requirements (data never leaves a region without explicit permission).
    • Proximity to customers (reduced latency).
    • Available services within a Region.
    • Pricing (varies region to region).

C. AWS Availability Zones (AZs)

  • Each region has multiple AZs (usually 3, min is 3, max is 6).
  • An AZ is one or more discrete data centers with redundant power, networking, and connectivity.
  • AZs are separate to be isolated from disasters.
  • Connected with high bandwidth, ultra-low latency networking.

D. AWS Points of Presence (Edge Locations)

  • Amazon has 400+ Points of Presence (400+ Edge Locations & 10+ Regional Caches) in 90+ cities across 40+ countries.
  • Used to deliver content to end users with lower latency.

E. Global vs. Region-scoped Services

Global Services:

  • Identity and Access Management (IAM).
  • Route 53 (DNS service).
  • CloudFront (Content Delivery Network).
  • WAF (Web Application Firewall).

Region-scoped Services (Examples):

  • Amazon EC2 (IaaS), Elastic Beanstalk (PaaS), Lambda (Function as a Service), Rekognition (SaaS).

4. Shared Responsibility Model

A. Core Responsibilities (Crucial Exam Concept)

  • AWS Responsibility – Security of the Cloud:
    • Protecting infrastructure (hardware, software, facilities, and networking).
    • Includes managed services like S3, DynamoDB, RDS.
  • Customer Responsibility – Security in the Cloud:
    • For EC2, management of the guest OS (including security patches and updates).
    • Firewall & network configuration (Security Groups rules).
    • IAM management, and encrypting application data.
  • Shared Controls: Patch Management, Configuration Management, Awareness & Training.

B. AWS Acceptable Use Policy

Prohibits: Illegal, Harmful, or Offensive Use or Content, Security Violations, Network Abuse, E-Mail or Other Message Abuse.

5. AWS Identity & Access Management (IAM)

A. IAM Fundamentals

  • IAM is a Global service.
  • The Root account should not be used or shared.
  • Users: Mapped to a physical user; have a password for the AWS Console.
  • Groups: Contain users only (not other groups). Permissions should be assigned to groups.
  • Roles: Used to assign permissions to AWS services (like EC2 instances, Lambda functions) to perform actions on your behalf. Common roles: EC2 Instance Roles, Lambda Function Roles.
  • Policies: JSON documents that define permissions. Follow the least privilege principle (don't give more permissions than necessary).
    • Policy Structure Components: Version ("2012-10-17"), Id (optional), Statement (required).
    • Statement Components: Sid (optional), Effect (Allow, Deny), Principal, Action, Resource, Condition (optional).

B. Security Features and Access

IAM Password Policy:

Allows setting minimum length, requiring specific character types (uppercase, lowercase, numbers, non-alphanumeric characters), password expiration, and preventing password re-use.

Multi Factor Authentication (MFA):

Password you know+security device you own. Prevents account compromise if a password is stolen.

  • MFA Device Options: Virtual MFA devices (Google Authenticator, Authy), Universal 2nd Factor (U2F) Security Key (YubiKey), Hardware Key Fob MFA Device (Gemalto, SurePassID).

Methods to Access AWS:

  1. AWS Management Console (password + MFA protected).
  2. AWS Command Line Interface (CLI) (access keys protected).
  3. AWS Software Developer Kit (SDK) (access keys protected).
  • Access Keys: Used for programmatic access (CLI / SDK). They are secret and must never be shared.
    • Access Key ID ≈ username, Secret Access Key ≈ password.
  • AWS CLI: Tool to interact with AWS services using commands; alternative to Console.
  • AWS SDK: Language-specific APIs (libraries) to manage AWS services programmatically. (CLI is built on the SDK for Python).

C. IAM Auditing Tools

  • IAM Credentials Report (account-level): Lists all users and the status of their credentials.
  • IAM Access Advisor (user-level): Shows service permissions granted and when those services were last accessed; used to revise policies.

6. Amazon EC2 (Elastic Compute Cloud)

A. EC2 Overview (IaaS)

  • EC2 = Elastic Compute Cloud = Infrastructure as a Service.
  • Fundamental concept: renting virtual machines (EC2).
  • Involves storing data on virtual drives (EBS), distributing load (ELB), and scaling (ASG).

B. EC2 Configuration and User Data

Configuration Options:

OS (Linux, Windows, Mac OS), CPU, RAM, Storage (network-attached/EBS, hardware/Instance Store), Network card speed/Public IP, Firewall rules (Security Group), and Bootstrap script (EC2 User Data).

EC2 User Data:

Script used to bootstrap instances (launch commands when machine starts).

  • Only run once at the instance first start.
  • Automates boot tasks (installing updates/software).
  • Runs with the root user.

C. EC2 Instance Types (Optimization)

  • Naming Convention example: m5.2xlarge (m: class, 5: generation, 2xlarge: size).
  • General Purpose (e.g., t2.micro, m-class): Balance of Compute, Memory, Networking. Good for web servers/code repositories.
  • Compute Optimized (c-class): High performance processors. Use cases: Batch processing, Media transcoding, HPC, Scientific modeling/ML, Dedicated gaming servers.
  • Memory Optimized (r-class): Fast performance for large data sets in memory. Use cases: High performance relational/non-relational databases, Distributed web scale cache stores, In-memory databases for BI.
  • Storage Optimized (i-class, d-class): High, sequential read/write access to large data sets on local storage. Use cases: High frequency OLTP systems, Relational & NoSQL databases, Data warehousing.

D. Security Groups (SG) (Firewall)

  • Security Groups are the fundamental of network security in AWS; act as a "firewall" on EC2 instances.
  • Controls traffic allowed into or out of EC2 Instances.
  • Key Rules/Behavior:
    • Can be attached to multiple instances.
    • Locked down to a region / VPC combination.
    • Lives "outside" the EC2 instance.
    • All inbound traffic is blocked by default.
    • All outbound traffic is authorised by default.
    • Troubleshooting: Time out issue ⇒ Security Group issue. "Connection refused" ⇒ Application error or not launched.

Classic Ports to Know (Exam Focus):

  • 22 = SSH (Secure Shell) - log into a Linux instance.
  • 21 = FTP (File Transfer Protocol) – upload files.
  • 22 = SFTP (Secure File Transfer Protocol) – upload files using SSH.
  • 80 = HTTP – unsecured websites.
  • 443 = HTTPS – secured websites.
  • 3389 = RDP (Remote Desktop Protocol) – log into a Windows instance.

E. EC2 Access and Purchasing Options

EC2 Instance Connect:

Connects to EC2 instance within your browser. Uploads a temporary key onto EC2. Works primarily with Amazon Linux 2.

Purchasing Options (Comparison):

  1. On-Demand Instances: Highest cost, no upfront commitment. Billing per second (Linux/Windows) or per hour (other OS). Recommended for short-term and un-interrupted workloads.
  2. Reserved Instances (RIs): Up to 72% discount. For steady-state usage applications (e.g., databases). Commitment for 1 year or 3 years. Payment options: No Upfront, Partial Upfront, All Upfront.
  3. Convertible Reserved Instances: Up to 66% discount. Can change instance type/family/OS/scope/tenancy.
  4. Savings Plans: Up to 72% discount. Commitment based on an amount of usage (e.g., $10/hour) for 1 or 3 years. EC2 Savings Plan is flexible across size/OS/tenancy within a family/region.
  5. Spot Instances: Up to 90% discount. Can be "lost" (interrupted) at any point if the max price is exceeded. MOST cost-efficient. Useful for workloads resilient to failure (batch jobs, data analysis). Not suitable for critical jobs or databases.
  6. Dedicated Hosts: Book an entire physical server. Most expensive option. Used for compliance requirements or server-bound software licenses (BYOL).
  7. Dedicated Instances: Run on hardware dedicated to you, but may share hardware with other instances in the same account.
  8. Capacity Reservations: Reserve On-Demand capacity in a specific AZ for any duration. No billing discounts. Charged at On-Demand rate whether you run instances or not.

7. Amazon EC2 Instance Storage

A. EBS Volumes (Network Drive)

  • An EBS (Elastic Block Store) Volume is a network drive (like a "network USB stick").
  • Allows instances to persist data after termination.
  • Can only be mounted to one instance at a time (at CCP level).
  • Bound (locked) to a specific Availability Zone (AZ). To move across AZs, you must snapshot it.
  • Billed for all provisioned capacity (size in GBs, IOPS).
  • Delete on Termination: Default behavior is the root EBS volume is deleted; other attached volumes are not deleted.

B. EBS Snapshots and Archiving

  • EBS Snapshots: Backup of an EBS volume at a point in time. Can copy snapshots across AZ or Region.
  • EBS Snapshot Archive: Move snapshots to an archive tier that is 75% cheaper. Restoring takes 24 to 72 hours.
  • Recycle Bin for EBS Snapshots: Retains deleted snapshots to recover from accidental deletion (retention from 1 day to 1 year).

C. AMIs and Instance Store

  • AMI (Amazon Machine Image): A customization of an EC2 instance. Built for a specific region. Provides faster boot / configuration time.
  • EC2 Image Builder: Automates the creation, maintenance, validation and testing of EC2 AMIs or container images. It is a Free service (pay for underlying resources).
  • EC2 Instance Store: A high-performance hardware disk physically attached to the EC2 instance.
    • Provides better I/O performance.
    • It is ephemeral: storage is lost if the instance is stopped.
    • Good for: buffer, cache, scratch data, temporary content.

D. Shared File Systems (EFS & FSx)

  • EFS (Elastic File System): Managed NFS (network file system).
    • Can be mounted on 100s of EC2 instances.
    • Works with Linux EC2 instances in multi-AZ.
    • Highly available, scalable, but expensive (3x gp2).
    • EFS Infrequent Access (EFS-IA): Cost-optimized for files not accessed every day (up to 92% lower cost). Enabled via a Lifecycle Policy (e.g., move files after 60 days of no access).
  • Amazon FSx: Launch 3rd party high-performance file systems.
    • FSx for Windows File Server: Managed Windows native shared file system. Supports SMB protocol & Windows NTFS. Integrated with Microsoft Active Directory.
    • FSx for Lustre: High-performance, scalable file storage for High Performance Computing (HPC). Name derived from "Linux" and "cluster". Scales up to 100s GB/s, millions of IOPS, sub-ms latencies.

8. Elastic Load Balancing & Auto Scaling Group

A. Scalability and High Availability

  • Vertical Scalability: Increasing the size of an instance (scale up/down). Common for databases.
  • Horizontal Scalability (Elasticity): Increasing the number of instances (scale out/in). Achieved using ASG and Load Balancer.
  • High Availability (HA): Running the application in at least 2 Availability Zones to survive a data center loss.
  • Elasticity: Automatic scaling based on load (pay-per-use, optimize costs).

B. Elastic Load Balancer (ELB)

  • ELB is a managed load balancer (AWS handles maintenance, HA).
  • Why use ELB? Spread load, expose a single point of access (DNS), handle failures, perform health checks, provide SSL termination (HTTPS).
  • 4 Types of Load Balancers:
    1. Application Load Balancer (ALB): HTTP / HTTPS / gRPC protocols (Layer 7). Supports HTTP routing features.
    2. Network Load Balancer (NLB): TCP / UDP protocols (Layer 4). Ultra-high performance (millions of request per seconds). Provides Static IP through Elastic IP.
    3. Gateway Load Balancer (GWLB): GENEVE Protocol on IP Packets (Layer 3). Routes traffic to firewalls/security appliances managed on EC2 instances.
    4. Classic Load Balancer (CLB): Retired in 2023.

C. Auto Scaling Group (ASG)

  • Goal: Implement Elasticity. Scale out/in to match load, ensure minimum/maximum machines run, automatically register to load balancer, and replace unhealthy instances.
  • Scaling Strategies:
    • Manual Scaling.
    • Dynamic Scaling: Respond to changing demand.
      • Simple / Step Scaling: Triggered by CloudWatch alarm (e.g., CPU > 70%).
      • Target Tracking Scaling: Keep average metric at a target value (e.g., average CPU at 40%).
    • Scheduled Scaling: Anticipate scaling based on known usage patterns.
    • Predictive Scaling: Uses Machine Learning to predict future traffic and provisions EC2 instances in advance.

9. Amazon S3 (Simple Storage Service)

A. S3 Fundamentals

  • S3 stores objects (files) in buckets (directories).
  • Buckets must have a globally unique name.
  • Buckets are defined at the region level.
  • Objects have a Key (the FULL path: s3://my-bucket/my_file.txt).
  • Max. Object Size is 5TB (5000GB). For uploads over 5GB, use "multi-part upload".
  • Objects have Metadata and up to 10 Tags.

B. S3 Security and Access

  • Access depends on IAM Policies (user-based) OR Resource-Based policies (Bucket Policies, ACLs). Access is granted if IAM ALLOWS OR Resource Policy ALLOWS AND there is NO explicit DENY.
  • Bucket Policies (Resource-based): JSON documents used to: grant public access, force encryption, grant Cross Account access.
  • Bucket settings for Block Public Access: Settings designed to prevent company data leaks; should be left on if the bucket should never be public.
  • Static Website Hosting: S3 can host static websites. If a 403 Forbidden error occurs, check the bucket policy for public read permissions.

C. Versioning and Replication

  • S3 Versioning: Enabled at the bucket level. Best practice to enable.
    • Protects against unintended deletes and allows roll back.
    • Unversioned files receive version "null" upon enabling.
    • Suspending versioning does not delete previous versions.
  • S3 Replication (CRR & SRR): Requires Versioning to be enabled on both source and destination buckets. Copying is asynchronous.
    • Cross-Region Replication (CRR): For compliance, lower latency access.
    • Same-Region Replication (SRR): For log aggregation, live replication between production/test accounts.

D. S3 Storage Classes (Critical Exam Comparison)

All classes share 99.999999999% (11 9's) Durability across multiple AZs. Availability varies.

  • S3 Standard – General Purpose: 99.99% Availability. Frequently accessed data. Sustains 2 concurrent facility failures.
  • S3 Standard-Infrequent Access (IA): 99.9% Availability. Data accessed less often, but requires rapid access. Min. Storage Duration: 30 Days.
  • S3 One Zone-Infrequent Access (One Zone-IA): 99.5% Availability. High durability in a single AZ; data is lost if AZ is destroyed. Min. Storage Duration: 30 Days.
  • S3 Intelligent-Tiering: Automatically moves objects between tiers based on usage. Includes a small monthly monitoring fee. No retrieval charges. Tiers adjust based on 30 days/90 days of no access.
  • S3 Glacier Instant Retrieval: Millisecond retrieval. Great for data accessed once a quarter. Min. Storage Duration: 90 days.
  • S3 Glacier Flexible Retrieval: Retrieval options: Expedited (1 to 5 minutes), Standard (3 to 5 hours), Bulk (5 to 12 hours – free). Min. Storage Duration: 90 days.
  • S3 Glacier Deep Archive (Long Term): Retrieval options: Standard (12 hours), Bulk (48 hours). Min. Storage Duration: 180 days.
  • S3 Express One Zone: High performance, single AZ storage class. Up to 10x better performance than S3 Standard. Used for latency-sensitive apps (AI & ML training, HPC).

E. Data Migration and Hybrid Storage

  • AWS Snowball: Portable devices to collect/process data at the edge and migrate up to Petabytes of data. Use if transfer takes more than a week over the network.
    • Edge Computing: Snowball Edge devices run EC2 Instances or Lambda functions at the edge.
    • Data transfer IN to Amazon S3 is $0.00 per GB.
    • Snowball Edge Storage Optimized: Provides 210 TB of storage.
  • AWS Storage Gateway: A hybrid storage service that acts as a bridge between on-premise data and cloud data in S3. Used for DR, backup, tiered storage. Types: File Gateway, Volume Gateway, Tape Gateway.

10. Databases & Analytics

A. Database Types

  • Relational Databases (SQL): Structured data, links between tables, uses SQL for queries.
  • NoSQL Databases (Non-Relational): Purpose built for specific data models, flexible schemas. Benefits: Flexibility, Scalability (distributed clusters), High-performance. Examples: Key-value, document, graph, in-memory.

B. Managed Relational Databases (RDS & Aurora)

  • Amazon RDS (Relational Database Service): Managed DB service using SQL.
    • Supported Engines: Postgres, MySQL, MariaDB, Oracle, Microsoft SQL Server, IBM DB2, Aurora.
    • Advantages: Automated provisioning/OS patching, Continuous backups (Point in Time Restore), Multi AZ setup for DR. You cannot SSH into RDS instances.
    • Read Replicas: Scale the read workload (up to 15 replicas). Supports Multi-Region DR.
    • Multi-AZ: Used for Failover/High Availability; only 1 other AZ as failover.
  • Amazon Aurora: AWS proprietary DB. 5x performance improvement over MySQL on RDS.
    • Storage grows in increments of 10GB, up to 128 TB.
    • Aurora Serverless: Automated instantiation and auto-scaling. Least management overhead; good for infrequent/unpredictable workloads.

C. Caching and NoSQL

  • Amazon ElastiCache: Managed in-memory databases (Redis or Memcached). High performance, low latency, reduces load on primary DB.
  • DynamoDB: Fully Managed NoSQL database (key/value). Highly available (replication across 3 AZ). Serverless. Single-digit millisecond latency.
  • DynamoDB Accelerator (DAX): Fully Managed in-memory cache for DynamoDB. 10x performance improvement. DAX is integrated with and only used for DynamoDB (CCP distinction from ElastiCache).
  • DynamoDB Global Tables: Provides low latency access in multiple regions using Active-Active replication.
  • DocumentDB: AWS implementation for MongoDB (JSON/document NoSQL database). Fully Managed, highly available (3 AZ).
  • Amazon Neptune: Fully managed graph database. Optimized for complex queries on highly connected datasets (e.g., social networking, fraud detection).

D. Analytics and Data Processing

  • Redshift: Used for OLAP – online analytical processing (analytics and data warehousing). Columnar storage; scales to PBs of data. Based on PostgreSQL.
    • Redshift Serverless: Automatically provisions and scales capacity; run analytics without managing infrastructure.
  • Amazon EMR (Elastic MapReduce): Helps create Hadoop clusters (Big Data) to analyze vast amounts of data. Also supports Apache Spark, HBase, Presto, Flink.
  • Amazon Athena: Serverless query service to analyze data stored directly in Amazon S3 using standard SQL. Pricing is $5.00 per TB of data scanned.
  • Amazon QuickSight: Serverless machine learning-powered business intelligence service to create interactive dashboards. Uses per-session pricing.
  • Amazon Timestream: Fully managed, serverless time series database.
  • AWS Glue: Managed extract, transform, and load (ETL) service. Fully serverless. Contains Glue Data Catalog.
  • DMS (Database Migration Service): Quickly and securely migrate databases to AWS. The source database remains available during migration. Supports Homogeneous (Oracle to Oracle) and Heterogeneous (SQL Server to Aurora) migrations.

11. Other Compute Services

A. Containers and Registries

  • Docker: Platform where apps are packaged in containers to run consistently on any OS. Containers scale quickly (seconds).
  • Amazon ECR (Elastic Container Registry): Private Docker Registry on AWS; stores images for ECS or Fargate.
  • ECS (Elastic Container Service): Run Docker containers on AWS; user provisions & maintains EC2 instances (infrastructure).
  • Fargate: Serverless offering for running Docker containers; user does not provision the infrastructure (no EC2 instances to manage).
  • Amazon EKS (Elastic Kubernetes Service): Managed Kubernetes clusters on AWS. Kubernetes is cloud-agnostic. Containers hosted on EC2 instances or Fargate.

B. Serverless Functions (Lambda)

  • Serverless: Paradigm where developers deploy code/functions and do not manage servers.
  • AWS Lambda (Function as a Service):
    • Scaling is automated.
    • Limited by time (short executions, max invocation time up to 15 minutes).
    • Pricing: Pay per request (First 1,000,000 requests are free) and pay per duration (400,000 GB-seconds free/month).
    • Increasing RAM improves CPU and network.
  • Amazon API Gateway: Fully managed service to create, publish, and secure APIs (RESTful and WebSocket). Used to expose Lambda functions as HTTP APIs.

C. Batch Processing and Simple Deployments

  • AWS Batch: Fully managed batch processing (jobs with a start and end). Runs 100,000s of computing jobs efficiently. Jobs are defined as Docker images and run on ECS.
  • Amazon Lightsail: Simplified alternative to EC2/RDS/ELB. Offers virtual servers, storage, databases with Low & predictable pricing. Great for IT beginners. No auto-scaling.

12. Deploying & Managing Infrastructure at Scale

A. Infrastructure as Code (IaC)

  • CloudFormation: Declarative way of outlining infrastructure (IaC). Creates resources in the right order.
    • Benefits: Cost tracking (tagged resources), easy destroy/re-create, declarative programming handles orchestration.
  • AWS Cloud Development Kit (CDK): Define infrastructure using a familiar programming language (Python, Java, etc.). Code is "compiled" into a CloudFormation template (JSON/YAML).

B. Application Deployment Services

  • AWS Elastic Beanstalk (PaaS): Developer centric view for deploying apps. Beanstalk is free (you pay for underlying resources).
    • Managed Tasks: OS management, Load balancing & auto-scaling, Health monitoring.
    • Architectures: Single Instance (dev), LB + ASG (production web apps), ASG only (non-web workers).
  • AWS CodeDeploy: Automates application deployment. A Hybrid service; works with EC2 Instances and On-Premises Servers (requires CodeDeploy Agent).
  • AWS CodeCommit: Source-control service hosting Git-based repositories. (Note: Discontinued July 25th 2024 for new customers; may still appear on exam).
  • AWS CodeBuild: Serverless code building service. Compiles source, runs tests, produces deployment packages. Pay-as-you-go pricing.
  • AWS CodePipeline: Orchestrates the steps for CICD (Code → Build → Test → Deploy).
  • AWS CodeArtifact: Manages software packages / dependencies (artifacts). Works with Maven, Gradle, npm, etc..

C. Systems Manager (SSM)

  • AWS Systems Manager (SSM): Helps manage EC2 and On-Premises systems at scale (Hybrid service). Requires the SSM agent installed on systems.
    • Features: Patching automation, Run commands across servers, SSM Parameter Store.
    • SSM Session Manager: Starts a secure shell on servers. No SSH access, bastion hosts, or Port 22 needed.
    • SSM Parameter Store: Secure storage for configuration and secrets (API Keys, passwords). Serverless, uses IAM for access control.

13. Global Infrastructure (Part 2)

A. Global Application Fundamentals

Global deployment decreases Latency and aids Disaster Recovery (DR).

B. Global Networking Services

  • Amazon Route 53 (Global DNS): Managed DNS service.
    • Alias Records link a hostname to AWS resources (ELB, S3, CloudFront).
    • Routing Policies: Simple, Weighted, Latency, and Failover (for DR, requires Health Check).
  • Amazon CloudFront (CDN): Improves read performance by caching content at Edge Locations. Provides DDoS protection.
    • Origins: S3 bucket (secured via Origin Access Control - OAC), VPC Origin (ALB/EC2), Custom Origin.
    • CloudFront vs. S3 CRR: CloudFront is for static content cached globally for a TTL; CRR is for dynamic content replicated near real-time in few regions.
  • S3 Transfer Acceleration: Uses AWS Edge locations to accelerate global uploads/downloads to S3.
  • AWS Global Accelerator: Improves global application performance using the AWS global network. Creates 2 Anycast IP addresses. No caching; proxies packets (TCP/UDP) at the edge. Good for static IP requirement/fast regional failover.

C. Hybrid and Edge Infrastructure

  • AWS Outposts: Server racks offering the same AWS infrastructure, services, APIs & tools in your on-premises data center. You manage the physical security of the rack.
  • AWS WaveLength: Infrastructure deployments at the edge of 5G networks within telecommunication providers' datacenters. Enables Ultra-low latency applications (e.g., connected vehicles, real-time gaming).
  • AWS Local Zones: Extends a VPC to places AWS compute/storage/database closer to end users. Used for latency-sensitive applications.

14. Cloud Integration

A. Decoupling Applications (Messaging)

  • Synchronous (app to app) communication is problematic with traffic spikes; Asynchronous/Event based (queue model) is preferred for decoupling.
  • Amazon SQS (Simple Queue Service): Queue service used to decouple applications.
    • Standard Queue: Scales highly (10,000s messages/second). Messages kept up to 14 days (default 4 days). Messages deleted after being read.
    • FIFO Queue: Guarantees First In First Out (ordering) of messages.
  • Amazon SNS (Simple Notification Service): Notification service (pub/sub model).
    • One message sent to many receivers (each subscriber gets all messages).
    • Subscribers include: SQS, Lambda, HTTP(S) Endpoints, Emails.
    • No message retention.
  • Amazon MQ: Managed message broker service for traditional applications that use open protocols (MQTT, AMQP, STOMP). Used for cloud migration instead of re-engineering to SQS/SNS.

B. Streaming Data

  • Amazon Kinesis: Used for real-time big data streaming.
    • Kinesis Data Streams: Low latency streaming to ingest data.
    • Amazon Data Firehose: Loads Kinesis streams into destinations (S3, Redshift).

15. Cloud Monitoring

A. CloudWatch

  • CloudWatch Metrics: Provides metrics for every AWS service. Default EC2 metrics are every 5 minutes (Detailed Monitoring is every 1 minute).
    • EC2 metrics include CPU Utilization and Network (NOT RAM).
    • Billing metric is available only in us-east-1.
  • CloudWatch Alarms: Trigger notifications for any metric. Actions include Auto Scaling, EC2 Actions (stop, terminate, reboot), and SNS notifications. Alarm States: OK, INSUFFICIENT_DATA, ALARM.
  • CloudWatch Logs: Collects logs from Lambda, ECS, Beanstalk, and using the CloudWatch agent installed on EC2/on-premises servers.

B. Eventing and Auditing

  • Amazon EventBridge (formerly CloudWatch Events):
    • Schedule: Used for Cron jobs (e.g., trigger every 1 hour).
    • Event Pattern: Reacts to service events (e.g., S3 upload, CodeBuild failed).
    • Features include Schema Registry and the ability to replay archived events.
  • AWS CloudTrail: Provides governance, compliance, and audit. It is enabled by default.
    • Records an history of events / API calls made in your account (Console, SDK, CLI).
    • If a resource is deleted, investigate CloudTrail first.

C. Application Observability

  • AWS X-Ray: Provides visual analysis and tracing for requests made through distributed applications. Helps troubleshoot performance, pinpoint service issues, and find errors/exceptions.
  • Amazon CodeGuru: ML-powered service for automated recommendations.
    • CodeGuru Reviewer: Automated code reviews for static code analysis (development). Supports Java and Python.
    • CodeGuru Profiler: Analyzes application performance during runtime (production). Helps decrease compute costs and identify expensive lines of code.

D. Health Dashboards

  • AWS Health Dashboard – Service History: Shows the health status of all AWS services across all regions (previously Service Health Dashboard).
  • AWS Health Dashboard – Your Account: Provides a personalized view and alerts when AWS events impact your resources (previously Personal Health Dashboard).

16. Amazon VPC (Virtual Private Cloud)

A. Networking Components (CCP Focus)

  • VPC (Virtual Private Cloud): A private network (regional resource).
  • Subnets: Network partitions tied to an AZ (AZ resource).
    • Public Subnet: Accessible from the internet.
    • Private Subnet: Not accessible from the internet.
  • Internet Gateway (IGW): Provides Internet Access to the VPC (at the VPC level).
  • NAT Gateways: Allow instances in Private Subnets to access the internet.
  • Elastic IP (EIP): Fixed public IPv4 address. Charged $0.005 per hour if not in-use.

B. Network Security Layers (Comparison)

Feature Security Group (SG) Network ACL (NACL)
Level EC2 Instance level / ENI Subnet level
State Stateful Stateless
Rules ALLOW rules only (inbound is blocked by default) ALLOW and DENY rules
References IP addresses AND other security groups IP addresses only

C. Connectivity and Logging

  • VPC Flow Logs: Captures information about IP traffic (into/out of interfaces). Helps troubleshoot connectivity issues. Data can go to S3, CloudWatch Logs, Firehose.
  • VPC Peering: Connects two VPCs privately (non-overlapping CIDR ranges). The connection is non-transitive.
  • VPC Endpoints: Provides private access to AWS Services (e.g., S3, DynamoDB, CloudWatch) from within your VPC, avoiding public internet.
    • VPC Endpoint Gateway: S3 & DynamoDB.
    • VPC Endpoint Interface (ENI): Most services.
  • AWS PrivateLink: Secure & scalable way to connect to a service in a 3rd party VPC.
  • Site to Site VPN: Encrypted connection over the public internet between on-premises DC and AWS.
  • Direct Connect (DX): Establishes a physical, private connection to AWS. Takes at least a month to establish.
  • Transit Gateway: Provides transitive peering to connect thousands of VPCs and on-premises networks (hub-and-spoke configuration).

17. Security & Compliance (Part 2)

A. Protection Services (DDoS, WAF, Encryption)

DDoS Protection:

  • AWS Shield Standard: Free; activated for all customers. Protects against Layer 3/Layer 4 attacks (SYN/UDP Floods).
  • AWS Shield Advanced: Paid service ($3,000 per month). Protects against sophisticated attacks. Includes 24/7 access to AWS DDoS response team (DRP).
  • AWS WAF (Web Application Firewall): Protects web applications from common web exploits (Layer 7 - HTTP). Deployed on ALB, API Gateway, CloudFront. Protects against SQL injection and XSS.
  • AWS Network Firewall: Protects the entire Amazon VPC from Layer 3 to Layer 7.
  • AWS Firewall Manager: Manages security rules (WAF, Shield, Network Firewall, SGs) across all accounts of an AWS Organization.
  • Data Encryption: We must encrypt data at rest (stored/archived) and in transit (in motion/transferred on network).
  • AWS KMS (Key Management Service): AWS manages the encryption keys. Used for encrypting EBS, S3 (SSE-KMS opt in), RDS, EFS, etc..
  • CloudHSM: AWS provisions encryption hardware. You manage your own encryption keys entirely. FIPS 140-2 Level 3 compliance.
  • AWS Certificate Manager (ACM): Provision, manage, and deploy SSL/TLS Certificates for in-flight encryption (HTTPS). Free of charge for public TLS certificates.
  • AWS Secrets Manager: Stores secrets; capability to force rotation of secrets every X days. Encrypts secrets using KMS. Mostly meant for RDS integration.

B. Security Detection and Auditing

  • Amazon GuardDuty: Intelligent Threat discovery using Machine Learning. Input data: CloudTrail Events Logs, VPC Flow Logs, DNS Logs. One click to enable (30 days trial).
  • Amazon Inspector: Automated Security Assessments. Targets: EC2 instances (leveraging SSM agent for OS vulnerabilities/network reachability), Container Images (ECR), and Lambda Functions.
  • AWS Config: Helps with auditing and recording compliance by tracking configurations and changes over time. A per-region service.
  • AWS Macie: Uses ML to discover and protect sensitive data, such as personally identifiable information (PII), primarily in S3 Buckets.
  • AWS Security Hub: A Central security tool that aggregates security findings (from Config, GuardDuty, Inspector, Macie) across multiple accounts. Requires AWS Config to be enabled first.
  • Amazon Detective: Analyzes/investigates findings (from GuardDuty, CloudTrail, VPC Flow Logs) to identify the root cause of security issues using ML and graphs.
  • AWS Artifact: Portal for on-demand access to AWS compliance documentation (ISO, PCI, SOC reports) and AWS agreements (BAA, HIPAA).
  • IAM Access Analyzer: Identifies which resources are shared externally (S3 Buckets, IAM Roles, KMS Keys, SQS queues, etc.).

C. Root User Privileges (Actions only the Root User can perform)

  1. Change account settings (name, email, password, access keys).
  2. View certain tax invoices.
  3. Close your AWS account.
  4. Restore IAM user permissions.
  5. Change or cancel your AWS Support plan.
  6. Register as a seller in the Reserved Instance Marketplace.
  7. Configure an S3 bucket to enable MFA.
  8. Edit or delete an S3 bucket policy with an invalid VPC ID/endpoint ID.
  9. Sign up for GovCloud.

18. Machine Learning

  • Amazon Rekognition: Find objects, people, text, scenes in images and videos. Use cases: Content Moderation, Celebrity Recognition.
  • Amazon Transcribe: Convert speech to text (uses ASR). Can automatically remove PII using Redaction.
  • Amazon Polly: Turn text into lifelike speech.
  • Amazon Translate: Natural and accurate language translation.
  • Amazon Lex: Technology powering Alexa; builds chatbots (uses ASR and Natural Language Understanding).
  • Amazon Connect: Cloud-based virtual contact center; 80% cheaper than traditional solutions.
  • Amazon Comprehend: Serverless service for Natural Language Processing (NLP). Finds insights, sentiment (positive/negative), and groups text by topic.
  • Amazon SageMaker AI: Fully managed service for developers/data scientists to build ML models.
  • Amazon Kendra: Fully managed document search service powered by ML. Extracts answers from within documents.
  • Amazon Personalize: Builds apps with real-time personalized recommendations (uses same technology as Amazon.com).
  • Amazon Textract: Extracts text, handwriting, and data from scanned documents (forms and tables).

19. Account Management, Billing & Support

A. Organizations and Account Management

  • AWS Organizations (Global Service): Manages multiple AWS accounts. Cost Benefits: Consolidated Billing (single payment method) and Pooling of Reserved EC2 instances.
  • Service Control Policies (SCP): Whitelist/blacklist IAM actions at the OU/Account level. Does not apply to the Master Account. SCPs apply to the Root user. Must have an explicit Allow.
  • AWS Control Tower: Sets up and governs a secure multi-account environment using best practices (automates policy management using guardrails).
  • AWS Resource Access Manager (RAM): Shares AWS resources (VPC Subnets, Transit Gateway) with other accounts. Avoids resource duplication.
  • AWS Service Catalog: Provides a self-service portal for users to launch pre-defined, authorized products.

B. Pricing and Cost Management

  • Pricing Models: Pay as you go, Save when you reserve, Pay less by using more (volume discount), Pay less as AWS grows.
  • Networking Costs: Traffic IN is free. Use Private IP instead of Public IP for savings.
  • Compute Savings Plan: Up to 66% discount. Flexible across Family, Region, OS, and Compute Options (EC2, Fargate, Lambda).
  • AWS Compute Optimizer: Recommends optimal AWS resources using ML to right-size workloads; can lower costs by up to 25%.
  • Cost and Usage Reports (CUR): Most comprehensive set of AWS cost and usage data (hourly/daily line items, tags).
  • Cost Explorer: Visualize costs, analyze usage, and forecast usage up to 12 months.
  • AWS Budgets: Creates budget alarms for costs, usage, reservations, and Savings Plans. Tracks RI utilization (EC2, ElastiCache, RDS, Redshift).
  • AWS Cost Anomaly Detection: Uses ML to detect unusual spending spikes without predefined thresholds.
  • AWS Service Quotas: Monitors when usage is close to a service quota threshold.

C. Support Plans and Trusted Advisor (Comparison)

  • Trusted Advisor: Provides recommendations across 6 categories: Cost optimization, Performance, Security, Fault tolerance, Service limits, Operational Excellence.
    • Basic Support (Free): Includes 7 core Trusted Advisor checks.
    • Business/Enterprise Support: Includes Full Set of Checks + API access.

Support Response Times:

  • Developer: General guidance < 24 business hours; System impaired < 12 business hours.
  • Business (24/7): General guidance < 24 business hours; System impaired < 12 business hours; Production system impaired < 4 hours; Production system down < 1 hour.
  • Enterprise On-Ramp (24/7): Production system impaired < 4 hours; Production system down < 1 hour; Business-critical system down < 30 minutes.
  • Enterprise (24/7): Production system impaired < 4 hours; Production system down < 1 hour; Business-critical system down < 15 minutes. (Also includes a designated Technical Account Manager (TAM)).

20. Advanced Identity

  • AWS STS (Security Token Service): Creates temporary, limited-privileges credentials. Used for identity federation and cross-account roles.
  • Amazon Cognito: Identity management for Web and Mobile applications users. Integrates with social providers.
  • AWS Directory Services:
    • AWS Managed Microsoft AD: Managed AD that supports trust relationship with on-premise AD.
    • AD Connector: Proxy to redirect directory requests to on-premise AD.
    • Simple AD: Cannot be joined with on-premise AD.
  • AWS IAM Identity Center (Successor to SSO): Provides one login for all AWS accounts in Organizations and business cloud applications (e.g., Salesforce).

21. Other AWS Services

  • Amazon WorkSpaces: Managed Desktop as a Service (DaaS) (Windows/Linux virtual desktops). Used to eliminate VDI management.
  • Amazon AppStream 2.0: Desktop Application Streaming Service; delivers applications to any computer via a web browser.
  • AWS IoT Core: Connects IoT devices to the AWS Cloud. Serverless, scalable to billions of devices and trillions of messages.
  • AWS Backup: Fully-managed service to centrally manage and automate backups. Supports PITR (Point-in-time Recovery) and Cross-Account Backup.
  • Disaster Recovery Strategies: Backup and Restore (lowest cost), Pilot Light, Warm Standby, Multi-Site / Hot-Site (highest cost).
  • AWS Elastic Disaster Recovery (DRS): Recovers physical, virtual, and cloud-based servers into AWS using Continuous block-level replication.
  • AWS DataSync: Moves large amounts of data from on-premises to AWS storage (S3, EFS, FSx). Replication tasks are incremental after first full load.
  • Cloud Migration Strategies (The 7Rs):
    • Retire: Turn off unneeded systems (10% to 20% cost savings).
    • Retain: Do nothing for now (due to compliance/dependencies).
    • Relocate: Move apps from on-premises to their cloud version, or move EC2 instances to a different VPC, AWS account, or AWS Region (e.g., VMware SDDC to VMware Cloud on AWS).
    • Rehost "lift and shift": Simple migration to AWS as is (e.g., using MGN). Could save up to 30% on cost.
    • Replatform "lift and reshape": Moving to a managed service (e.g., DB to RDS).
    • Repurchase "drop and shop": Moving to a different product (SaaS like Salesforce).
    • Refactor / Re-architect: Reimagining application using Cloud Native features (e.g., monolith to micro-services).
  • AWS Application Migration Service (MGN): Lift-and-shift solution for migrating servers to AWS.
  • AWS Fault Injection Simulator (FIS): Runs fault injection experiments on workloads (Chaos Engineering).
  • AWS Step Functions: Builds serverless visual workflows to orchestrate Lambda functions. Supports sequence, parallel, conditions, and human approval.
  • Amazon Pinpoint: Scalable 2-way marketing communications service (email, SMS, push). Used to create segments and full campaigns.

22. AWS Architecting & Ecosystem

A. Well-Architected Framework (6 Pillars)

The framework consists of 6 Pillars that work in synergy:

1. Operational Excellence:

Ability to run, monitor, and continually improve systems. Principles: Perform operations as code (IaC), Make frequent/small/reversible changes, Use managed services.

2. Security:

Protecting information, systems, and assets. Principles: Strong identity foundation (IAM, least privilege), Enable traceability (logs/metrics), Apply security at all layers, Protect data in transit and at rest.

3. Reliability:

Ability to recover from disruptions and meet demand. Principles: Test recovery procedures, Automatically recover from failure, Scale horizontally, Use Auto Scaling.

4. Performance Efficiency:

Efficient use of computing resources. Principles: Go global in minutes, Use serverless architectures, Experiment often.

5. Cost Optimization:

Running systems at the lowest price point. Principles: Adopt a consumption mode (pay only for what you use), Analyze and attribute expenditure (use tags), Use managed services.

6. Sustainability:

Minimizing environmental impacts. Principles: Maximize utilization (right size), Use managed services (e.g., S3 Intelligent Tiering, S3 Glacier), Use efficient hardware (Graviton 2, T instances).

  • AWS Well-Architected Tool: Free tool to review architectures against the 6 pillars and obtain advice.

B. AWS Cloud Adoption Framework (CAF)

  • Helps you plan and execute a comprehensive cloud transformation using AWS best practices and real-world lessons learned.
  • Core idea: build organizational capabilities across six perspectives to support transformation outcomes.
  • Perspectives (Foundational Capabilities):
    • Business: ensure cloud investment accelerates business outcomes (CFO view: “How does cloud help us grow revenue, reduce costs, innovate?”).
    • People: bridge business and technology (HR view: “Do our teams have skills, culture, and leadership to work in cloud?”).
    • Governance: maximize benefits and minimize transformation risk (PMO view: “Are we controlling costs, risks, and compliance while delivering value?”).
    • Platform: build an enterprise-grade cloud foundation and modernize workloads (IT/Engineering view: “Do we have the right cloud architecture, tools, and pipelines?”).
    • Security: protect data and workloads (Security team view: “Are we secure, compliant, and ready for threats?”).
    • Operations: run and improve cloud services at the level the business needs (Ops team view: “Can we monitor, fix, and scale services reliably?”).
  • Transformation domains:
    • Technology: migrate and modernize legacy infrastructure, applications, data, and analytics.
    • Process: digitize, automate, and optimize business operations (use data/analytics + ML for better insights and customer experience).
    • Organization: reimagine the operating model (organize teams around products/value streams; adopt agile ways of working).
    • Product: reimagine the business model by delivering new value propositions (products/services) and revenue models.
  • Transformation phases:
    • Envision: identify transformation opportunities and define how cloud accelerates outcomes.
    • Align: assess gaps across the 6 perspectives and create an action plan.
    • Launch: deliver pilot initiatives in production and prove incremental value.
    • Scale: expand successful pilots to realize the desired benefits.

C. Ecosystem and Support

  • AWS Right Sizing: Matching instance types/sizes to workload requirements at the lowest possible cost. Always start small. Important before and continuously after migration.
  • AWS Marketplace: Digital catalog of third-party software (AMI, templates, SaaS). Purchases go into the AWS bill.
  • AWS IQ: Quickly find and pay AWS Certified 3rd party experts for on-demand project work. Charges are added into your AWS Bill.
  • AWS re:Post: AWS-managed Q&A service (replaces Forums) for technical questions.
  • AWS Managed Services (AMS): Provides infrastructure and application support 24/365 to offload routine management tasks (change requests, monitoring, patching).
